## 使用者需協助的操作

1. **先在 V2.2 下載 JSON 並存到 iCloud Drive。** 勿替換正式版部署。V2.3 需獨立 HTTPS 測試網址；目前沒有發布測試網址。確定測試託管位置後才能設定 OAuth origin 及在 iPhone 使用。不要直接以 GitHub 原始碼頁或「檔案」HTML 預覽當成網站。
2. Google Cloud 建立／選擇專案，啟用 Google Calendar API，設定 OAuth consent screen，測試模式加入實際 Google 帳號為測試使用者。建立 **Web application** OAuth client，Authorized JavaScript origins 填入測試網站的精確 origin（協定＋網域＋port，不含路徑）。只需公開的 client ID，**不需要密碼或 client secret**。
3. 在 Google Calendar 建立專用「產險續保提醒」行事曆。從該行事曆「設定與共用 → 整合日曆」複製行事曆 ID，在 V2.3 填入 client ID 與行事曆 ID，按「連接 Google」並自行同意。舊原型預設 primary；新測試請先選定專用行事曆。同一組測試資料後續固定使用同一行事曆；不提供跨行事曆搬移功能。
4. 用測試保單驗收：到期日 2026/12/25 應建立 2026/11/25；改為 2027/03/31，應更新同一事件至 2027/02/28。已續保／不續保應取消提醒；重新改待續保應只留一筆。
5. 重複匯入清冊應新增 0 筆；再驗證關閉重開、未授權／離線／重新連線及「重新同步」的狀態。授權過期需親自再次連線，不能保證 Safari 靜默授權。
6. iPhone 安裝 Google Calendar、開啟該日曆同步及通知權限。可建立明天日期的提醒：把測試保單到期日設為明天往後一個月，先核對程式算出的提醒日期，保持事件通知設定。確認實際收到通知；全天事件的實際顯示時間依 Google／手機設定，尚未實機確認。不要用已過的提醒日期驗收推播。
7. 從 iPhone Safari 分享加入主畫面，固定從該圖示使用。測試下載 JSON → 存到 iCloud Drive → 還原，核對筆數、PDF 及行事曆無重複。這是手動備份，不是 iCloud 自動同步。

## 仍待驗收／限制

- Google Cloud 專案、client ID、獨立測試部署與使用者 OAuth 同意；未取得或代辦。
- Google 真實 API 回應及跨裝置併發、Safari 本機持久性、iCloud 還原、iPhone 通知。
- Web Locks 可用時序列化同源分頁；跨裝置依穩定事件 ID 及重試去重。不同裝置同時修改同一保單沒有衝突解決介面，以最後成功同步的內容為準；驗收前避免同時編輯。
- 未開啟網站時沒有背景同步；已建立的 Google 事件由 Google 通知。重新開啟後可能需再次授權。
- Google 失敗會顯示失敗數／原因並保留重試資訊，使用者排除網路或權限原因後按重新同步。沒有無限自動重試或後端排程。
- 跨裝置請使用同一 JSON 備份及同一專用行事曆。遺失映射又刪除本機保單時，程式不會猜測並刪除其他裝置事件，需人工核對。
- Excel 目前仍只讀第一張工作表、前 30 列尋找表頭，保留既有範圍。本次驗證檔案為單一工作表。
- `.ics` 仍為手動備用功能。不要將同一批保單同時以 ICS 與 API 匯入；外部手動匯入的事件不在 API 管理範圍。
- 正式發布及合併 main 尚未執行，需真實驗收後另行決定。
