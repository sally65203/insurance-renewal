# V2.3 Google Calendar 自動續保提醒 — 實作規格（開發中）

## 目標
- 保單來源：Excel 續保清冊及 PDF 新投保紀錄。
- 範圍：狀態非「已續保」、「不續保」，且具有有效到期日的所有保單。
- 提醒日：到期日往前一個曆月，若前月無同日，使用前月最後一天（例如 3/31 → 2/28）。
- 以台灣時區 Asia/Taipei 建立 Google Calendar 全天事件，並設定事件通知。
- 使用者可從 iPhone Google Calendar App 接收通知；通知實際顯示依帳號及手機設定。

## 必須完成的整合
1. 建立 Google Cloud OAuth 用戶端，配置已部署網站的 HTTPS origin；不得把 client secret 放入前端。
2. 前端使用 Google Identity Services 取得最小必要 Calendar 權限；使用者需主動同意。
3. 選擇或建立專用行事曆，記錄 calendarId；新增事件時以保單唯一 id 對應 Google eventId。
4. 新增／編輯／Excel 匯入／JSON 還原後執行差異比對：未完成續保則新增或更新，已續保／不續保則刪除舊提醒。
5. 確認 API 成功才更新本機同步紀錄；錯誤需明確顯示，可重新執行，不得宣稱成功。
6. Google API 可能限流、授權失效、網路中斷；需提供手動「重新同步」與失敗筆數。
7. 本機 IndexedDB 與 iCloud JSON 備份需包含同步對應資訊；避免不同裝置匯入備份後重複建立事件。
8. 不在 Google 行事曆標題、描述放置敏感個資或保費，除非使用者明確選擇。
9. 使用者未開啟網站時，純前端無法保證背景自動同步；如需不開啟網站也自動同步，須有可靠的後端排程及安全的憑證管理。
10. 維持 V2.2 正式版不變；在測試分支驗證後再決定發布。

## 目前已完成
- V2.3 測試分支加入 .ics 匯出功能；匯入 Google 行事曆仍是手動操作，非 OAuth API 同步。

## 尚未完成
- Google Cloud OAuth 設定與使用者授權。
- API 建立／更新／刪除事件及去重。
- iPhone 實機通知驗證。
- 正式版發布。

## 驗收案例
- 新增到期日 2026-12-25 保單：建立 2026-11-25 全天提醒。
- 修改到期日：更新同一事件，不新增第二筆。
- 標記已續保／不續保：移除對應事件。
- 重複匯入相同保單：不重複建立。
- 授權過期或離線：顯示失敗並允許重試。
- JSON 備份與還原：同步識別資訊不遺失。

## 已確認的正式同步方案（2026-10-25）
- 使用者選擇方案 A：開啟 Safari 手機續保系統時，在完成 Google OAuth 授權且網路可用的情況下，自動比對並同步保單提醒。
- 保單新增、修改、續保狀態異動及匯入後，亦應觸發同步；同步失敗需顯示狀態並提供重試。
- Google Calendar 已建立的事件負責在到期前一個月發出 iPhone 通知；系統未開啟時不會背景同步後續資料異動。
- 尚未完成 OAuth/API 程式整合，不能宣稱已具備自動通知。
